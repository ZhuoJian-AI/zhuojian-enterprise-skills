# 更新记录

## 1.1.22 - 2026-09-24

- 增加可选的 `aiSemantics.globalCheck` 契约：仅绑定同页获权、无需确认的只读 Action，输入为必填空 `context`，结果采用有界 `assistantCheck v1`；同一应用不得重复登记同一检查 Action。
- 跨页面检查只在员工登录、页面可见且在线时由 SaaS 低频发起；只返回有来源的核对提示，不创建第二个助手、后台 Run、离线通知或自动写入。旧的当前页 `proactiveCheck` 和 2.4／2.5 契约保持兼容。
- 这份 Skill 只约束以后接入与验收；现有 SaaS 运行时、生产协同 Action、企业授权及服务器部署必须分别完成，不能把更新 Skill 当成预警功能已上线。

## 1.1.21 - 2026-09-23

- 当前子系统已登记的四个受控主题色可用于同一 SaaS 助手的外框、顶部与输入控件，和模块导航、助手入口保持协调；桌面与手机使用同一规则。
- 回答正文、审批／错误语义状态、其他应用入口和业务 iframe 不受当前子系统主题染色；切换或离开应用及时换色／清除，旧登记缺失或无效主题时安全回退。
- 不新增 Manifest 字段、不修改 2.4／2.5 协议或子系统业务代码；Skill 约束不代替 SaaS 前端运行时代码和部署。

## 1.1.20 - 2026-09-22

- 将当前子系统四个受控主题令牌扩展为 SaaS 外壳的协调式视觉上下文：平台导航轨、通用操作和统一助手入口可使用边框、选中、焦点、图标与轻量晕染。
- 平台结构、名称、普通文字和助手内容继续保持中性；其他应用入口与 iframe 内容不得继承当前系统主题，切换系统同步换色，离开系统立即清除。
- 保持 `2.4/2.5` 契约与原有四字段 Schema 不变；现有子系统主题登记正确时无需修改业务代码或重新部署。

## 1.1.19 - 2026-09-22

- 新增与统一 SaaS 助手配套的目标交接和当前页业务提示契约及适配器：只进入带来源草稿，不自动发送、创建运行或批准业务写入。
- 新增可选流程知识与员工显式开启的当前页低频只读检查规范；开发 AI 从真实业务梳理流程和完成依据，SaaS 消费获权说明并执行受控检查，不引入第二个助手或独立模型配置。
- 强化资料归属冲突、批量部分成功与未知结果的证据核对及验收，不以文件名、候选顺序或请求 completed 代替业务真实性。
- 保持 2.4/2.5 兼容；新增能力须先验证 SaaS 后端能力发现、前端协商及员工实时权限。Skill 更新不等于 Runtime helper 或现有子系统已适配、发布，不提供后台监控或无人值守写入。

## 1.1.18 - 2026-09-22

- 将业务提效设计前置到新增/实质改造流程：开发 AI 主动识别重复劳动，负责人确认业务规则，统一助手完成获权查询、草稿及确认后操作；保留纯维护与人工方案的适用边界。
- 同步模块需求与开工模板，取消默认“AI 只能查不能改”，修正留痕代替权限及无数据即无异常的矛盾。
- 新增本地工程交接示例与只读校验器，核对真实页面/Action、平台可用性、验收证据和跨层待办；不将材料伪装成线上调度或 Manifest 扩展。
- 单一 SaaS 助手与统一供应商配置不变；后台主动任务必须有真实平台支持和明确委托。保持 2.4/2.5 兼容，不修改或部署 SaaS、Runtime、现有业务子系统。
