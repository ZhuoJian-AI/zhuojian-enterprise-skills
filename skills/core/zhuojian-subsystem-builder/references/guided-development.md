# AI 带我继续研发

使用场景是开发者说“带我一步一步做”，或从工作台的「让 AI 带我继续」带入项目。适合继续现有模块，也可用于刚建好的项目。需要先明确本轮想交付的一个业务结果。

## 先核对进度

把从工作台传来的项目名称、编号、身份和状态当作定位线索。用当前账号能访问的项目、对应源码、发布回执及工作台入口核对。碰到同名项目，按企业和项目编号确认，项目授权以当前平台为准。已经做好的步骤保留，按本轮范围从最早未完成或结果待核对的一步接续。

## 四步研发进度

使用当前本人灼见企业插件，先调用 `get_identity` 核对企业与员工身份，再通过 `get_development_project_progress` 按 `projectId` 读取该项目的 `progress`。如果没有项目编号，可省略它来列出本人获权的项目。项目编号和授权以实时结果为准。四个阶段依下表展示，每一步用对应的工具字段。

| 工作台阶段 | `stage` | 核对到什么才能标完成 |
| --- | --- | --- |
| 建立子模块 | `module` | 确认实际子模块和源码入口，记录模块标识以及建成或沿用结果。 |
| 设定功能 | `features` | 已确认业务场景、页面、操作和验收条件，并核对已实现的代表性流程。 |
| 设定数据库 | `database` | 至少核对数据模型、存储去向与代表性读写；如涉及迁移，注明实际验证环境。如无需数据库，写明原因和验证结果。 |
| 设定岗位 | `roles` | 梳理岗位、可进入的页面、可执行操作和数据范围，将角色写入当前模块 Manifest 的 `accessRoles`，验证角色限制并注明岗位已定义、已发布、已分配和员工验收的真实状态。 |

开始当前阶段、每得到一个可核验结果、遇到阻塞或完成阶段，都调用 `update_development_project_progress` 回写。提供 `projectId`、上次读取的 `expectedVersion`、当前 `stage`、`status` 与简要 `summary`。状态为 `pending`（待开始）、`in_progress`（进行中）、`blocked`（待解决）、`completed`（已完成）。摘要 1–320 字，只写项目成员看得懂的结果、验证环境或阻塞事项，省略凭据和业务数据明细。写成功后调用读取工具回读确认，再继续下一步。收到状态变化、网络超时或结果不明时，先读当前进度，再决定是否需要重新更新。缺少工具或写入权限时，交代已核实进展及同步阻塞，重新获权后依实况补录。

有该项目人员授权管理权时，在「系统研发 → 我的研发系统 → 权限一览」按角色看配置，按人员复核已生效的权限。分配员工角色沿用已获权的「业务角色与人员」或企业管理员操作流程，在确认分配对象和范围后办理。岗位完成只说明角色设计和验证状态，实际分配与员工访问单独核实。已获委托的负责人可由同一向导接着做分配，无需切换 Skill。

## 每次带完一步

面向开发者用三句话说明「已经核实」「现在做什么」「怎样算完成」。能在现有授权范围内完成的技术工作，由 AI 直接执行和验收。只有需要开发者做选择、使用本人会话或者由指定人员授权时，给他当前一步、准确入口和预期结果，等结果后继续相关步骤。已同意的动作沿用原授权。业务取舍不清楚时优先问一个能决定下一步的问题。

| 核对到的情况 | 接着做什么 |
| --- | --- |
| 需求或模块行为待确定 | 选一个代表性业务场景，用现有「模块需求」资料明确页面、操作、人员及验收条件。 |
| 模块已开发，候选尚未发布 | 双端验证，核对登记清单、业务角色和拟验收账号，按[现有发布流程](direct-ecs-deployment.md#发布与开放规则)处理获授权的发布。 |
| Runtime 已发布，工作台未接入 | 先核对发布回执、Manifest 登记及应用状态。项目负责人可以提交工作台接入。待关联时由企业管理员选择已经核验的应用。已登记的模块从现有接入继续。 |
| 工作台已接入，员工尚未开放 | 从[随研发交付业务角色](project-business-roles.md)核对页面、操作和范围。出现「业务角色与人员」且当前负责人有委托时，可发布角色和分配员工。其余项目请企业管理员办理。 |
| 角色已分配，员工尚未验收 | 请获权员工从工作台实际进入，完成一个代表性操作。按业务需求核对数据范围、无权操作和撤权，记录使用结果。 |

「健康」「已登记」「员工实际可用」用各自的证据。工作中断时，记录最后一步的结果、当前负责人和下一步。换聊天后先重新核对会变化的版本、授权和操作结果。
