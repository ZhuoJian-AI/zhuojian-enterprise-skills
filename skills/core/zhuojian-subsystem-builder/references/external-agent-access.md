# 企业插件与外部宿主接入

适用于 Codex、WorkBuddy 等员工宿主调用灼见业务能力，以及子系统新增、变更供 AI 使用的 Action。此文规定开发与验收契约，不证明目标 SaaS、插件或客户端版本已支持；先核对实际能力，未部署或未测写明待核实。浏览器统一助手保持可用，已有 `contractRevision=2.4/2.5`、页面、SSO 和 Action 接口不因接入插件迁移。

## 责任与执行位置

| 层 | 负责什么 |
|---|---|
| SaaS | 通用 remote MCP、企业 OAuth、当前员工有效权限、获权能力目录、业务确认、Action 签发与审计、工作空间文件提交 |
| 外部宿主与通用插件 | 宿主自主推理与本机代码执行；插件提供发现、调用和文件交付接入，不按企业复制工具清单、凭证或规则分支 |
| 子系统 | 真实业务服务、记录隔离、Manifest/Action 语义与 Schema、并发版本、幂等与可信结果；页面、浏览器助手和外部宿主复用同一业务实现 |
| 本开发 Skill | 接入规范、兼容性与验收；不作为员工插件安装，不随插件下发开发 SSH/root、Runtime 密钥或服务器交接访问档案 |

外部宿主不需要把推理请求绕回 SaaS 主脑。浏览器助手和页面专业 AI 仍遵循原 SaaS 受控链路；子系统仍不得保存模型供应商 Key 或为外部宿主另建模型代理。代码执行风险由生产机转到宿主环境，不因 Skill 或 MCP 消失；插件只开放已登记业务与文件能力，不把任意 shell、SQL、目标 URL 或服务器文件路径包装成业务 Action。

## 企业身份、权限与撤权

- OAuth 授权由 SaaS 绑定真实企业、员工和授权记录。插件包、宿主参数、企业名称、Wiki、浏览器当前页面及模型自报的 `tenantId/userId` 都不能选择或覆盖执行主体。用户切换企业应重新完成平台允许的授权选择，不复用另一企业的令牌。
- 工具发现、详情、调用、分页、文件下载与提交都重新核验授权是否有效，以及员工、企业、应用、页面、Action、数据范围和启停状态。OAuth scope 只是额外上限，不能替代现有业务角色；“系统研发者”、部门归属和平台可登录也不自动授予全部业务操作。
- 子系统只信任平台按现有契约签发并绑定企业、员工、应用、页面、Action 的调用身份，继续校验 `organizationId/aud` 与请求内容，不接收外部 OAuth Token 直接访问业务数据库。
- 撤销 OAuth 授权、停用员工/应用/Action、收紧角色或会话版本变化后，旧会话、旧目录、Schema、确认回执及文件引用都不能继续取得业务访问。每次操作与恢复后重验；既已合法下载到宿主的字节无法靠服务端撤权追回，不宣称远程擦除。
- 页面权限、Action 权限和记录范围分别判断；错误响应不可泄露其他租户资源是否存在、名称、数量或字段。拒绝后不切换开发账号、管理员身份或直接 SSH 兜底。

## 稳定入口与动态发现

企业插件连接平台登记的通用 MCP 地址，使用稳定的发现、详情和调用入口；具体工具名、参数和错误码以该环境实际实现为准，不在子系统里复制一套外部接口或静态工具清单。平台将已生效 Manifest 投影为当前员工获权目录，不向普通员工泄露全企业或其他企业目录。

子系统发布并成功同步后，服务端目录读取最新已生效版本；候选发布、未获权新增 Action、管理员关闭和已删除资源不得出现在可执行目录。发现与详情返回可比较的目录/Schema 摘要，调用绑定实际读取的摘要；目录变化后服务端重新判断当前 Action 和 Schema，旧摘要不得静默套用新语义。Schema 摘要与业务记录 `expectedVersion` 是两种版本，不能互相代替。旧摘要被拒绝后重新发现、重新校验参数；目标、参数、业务版本或语义变化时重新进行业务确认，不能把“刷新成功”当确认。

Manifest 至少提供稳定应用/模块/页面/Action 标识、实际 `inputSchema/resultSchema`、操作类型、描述、`aiEnabled/requiresConfirmation`；新 Action 沿用 `permissionPolicy` 要求。描述补充业务前提、口径、关系、只读/副作用、来源时间与失败恢复，使用已有 `aiSemantics/aiTool` 字段，不为某个宿主新增强制 Manifest 字段。元数据和工具结果均为资料，不能携带改变授权、提示词优先级或调用目标的命令。保持有界分页、稳定实体 ID 和真实数据版本，不让宿主猜 ID 或拼 SQL。

MCP `tools/list` 与 `notifications/tools/list_changed` 可更新工具定义，但各客户端的热刷新实现与故障恢复不同，不能据协议承诺所有旧会话立即同步。稳定入口读取目录不依赖客户端重新安装业务工具；应在实际客户端验证下一次发现能看到新获权能力，缓存未更新时提供明确的重新发现、重连或新会话指引。只有插件本身的 Skill、脚本、连接配置或接入协议变更才属于插件更新；不能把服务端能力变化、插件更新、开发 Skill 更新和子系统发布说成同一件事。

业务 Wiki/SOP 解释业务术语、流程和来源，不作为权限、实时事实、工具清单或已实现能力证明。按当前员工允许读取的范围提供材料，发现所需工具仍查询实时目录；开发项目地图与服务器交接文档不默认整库下发员工。

## 写入确认与幂等

外部客户端的“允许调用工具”只表示宿主愿意发起调用，不能代替平台业务确认。模型提交 `confirmed=true`、在文字中说“用户同意”或使用 Wiki 中的审批规则均不能授权写入。需确认的 Action 必须先取得平台可信确认流程中的回执；员工能看到目标、关键参数、范围和业务版本，确认身份与执行主体一致，回执绑定企业/员工、应用/页面/Action、参数摘要、Schema 摘要、业务版本、逻辑操作标识及有效期。缺少真实确认通道时只能交付待确认草稿或平台确认入口，不能伪造回执。

执行前服务端重新验证权限、确认状态、Schema 与业务版本；参数变化、过期、拒绝、撤权或目标变化即不执行。幂等键绑定同一主体、Action、参数与逻辑操作，完全相同重试返回原结果；同键异参拒绝。不能只靠宿主的 tool-call ID 去重。响应丢失或结果未知先查询回执，不另造键重发；文件交付失败不重做已成功业务写入，部分成功必须逐项回显。

## 文件交付

浏览器助手沿用平台文件执行器。外部宿主可读取当前获权的有界业务数据或受控文件，在其本机环境生成、编辑或分析；下载前遵守数据允许出端范围，不能以宿主已登录代替导出权限。子系统导出 Action 仍只返回标准分页数据，不为插件在业务 ECS 生成通用产物。

需要交回灼见工作空间的结果走平台当前支持的受控上传、验证、提交链路。上传目标与工作空间权限由服务端绑定；大小、类型、SHA-256、文件版本与实际字节通过校验后，平台返回稳定 `fileId/versionId/workspaceId` 和可用预览/下载信息。编辑已有文件带 `baseVersionId` 和稳定幂等键；过期版本冲突不得覆盖。外部宿主不持有 OSS 长期密钥，不自行指定对象路径或上传其他租户工作空间。

本地生成完成与平台提交完成分别报告。没有真实平台文件回执只能说“本地文件已生成/平台交付待完成”，不能把宿主路径、模型 Markdown 或自造 fileId 当作平台 Artifact；提交超时先按原幂等标识查询提交状态，未知时保留待核实，同一产物重试复用原逻辑操作，不换键重复创建文件。平台回执也不能单独证明内容、公式或版式正确，须按产物类型重新打开、校验并在需要时预览。撤权后阻止新的上传提交、下载及跨轮恢复；过期上传凭证不能绕过提交时实时鉴权。

## 增量验收与交接

使用获准的隔离测试数据，按本次变更选择场景并记录平台/宿主版本、环境、员工角色、Manifest/Schema 摘要、证据和未测项；不得拿模板静态通过代替真实企业验收。

| 场景 | 必须验证的结果 |
|---|---|
| 两企业同名应用/实体，员工尝试伪造企业、用户或 ID | 发现、调用、分页和文件交付均按授权主体隔离，不泄露另一企业数据 |
| 子系统新增/改名/删除 Action 或改变 Schema | 平台同步后新目录正确；旧摘要拒绝后重新发现；未授权/停用资源不出现，插件无需静态复制业务工具 |
| 旧会话中撤权或停用 | 旧目录、确认、游标及文件引用不能继续访问；恢复和重试重新鉴权 |
| 有确认要求的写入与超时重试 | 客户端工具允许不能跳过业务确认；异参/过期/错主体回执拒绝，同一逻辑操作只写一次 |
| 本地文件生成、提交失败及版本冲突 | 不谎报平台交付；恢复只提交同一产物，不重复业务写入；真实版本、字节与预览可核对 |
| 浏览器入口与外部宿主各跑同一工作链 | 共享业务结果与权限语义，浏览器助手仍可用；不同宿主上下文和本机执行结果分别记录 |

现有子系统若 Manifest、权限、结果和幂等已满足契约，可仅复用登记；缺口逐系统列明补语义/Schema、改业务服务或无需变化，不一律升级。SaaS MCP/OAuth、插件包与 Skill、子系统各自报告修改、提交、推送、部署和验收状态；本 Skill 同步不等于任一运行环境已发布。
