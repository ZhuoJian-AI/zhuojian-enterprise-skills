# 模块导航与安全迁移

模块是导航与授权边界，页面是访问边界，Action 是操作边界，数据范围限定可处理记录。页面内筛选、明细页签不必成为独立模块；需要独立导航与授权的业务区必须登记稳定 moduleKey，不把多个独立业务区隐藏在一个 main 页面。

## 嵌入布局

- SaaS 左侧选择系统，内容顶部用获权目录生成约 44px 高的横向模块导航。计数来自有效目录，不从页面标题或按钮数量推断。
- 子系统在首屏绘制前识别嵌入模式，隐藏重复系统、模块导航和外壳；独立打开保留自身导航。保留模块内多页面入口、筛选和详情页签。
- 默认业务内容边距约 16px，减少重复标题及无业务用途留白；不强制所有系统采用同一视觉风格。窄屏不产生整页横向滚动，宽表格在自身容器滚动。
- 深链接、前进后退、当前 pageKey 与 AI 上下文必须一致。不可见不代替后端授权，直接 API 和 AI 调用必须同样校验。

## 升级顺序

1. 只读盘点服务器实际源码、未同步修改、当前部署和 Manifest；保留服务器较新改动，不能直接用模板覆盖。
2. 输出系统、模块、页面、Action 的旧键与新键映射、保留/新增/移除状态。一个旧页面拆多个模块时，不能把旧页面权限复制到全部新模块。
3. 只有语义等价且不扩权的映射才可提出迁移；无法证明等价的项列为管理员待确认，不自动写真实授权。数据归属不明的记录不能按姓名认领。
4. 执行 `python <skill>/scripts/audit_permission_upgrade.py --current <新契约> --baseline <服务器原契约>`；新系统省略 baseline。新增 Action 缺少策略会失败，旧缺失项输出待升级列表。该检查只验证声明，不能证明实际隔离。
5. 每个新增策略须验证可信用户、企业边界、记录归属、支持范围、业务状态以及页面/AI 共用业务检查；个人固定本人，公共只读已发布字段，管理仅支持已实现范围。不得只补分类标签。
6. 使用独立测试身份完成越权、撤权、旧链接、导航、页面和 Action 回归，再部署、登记并核对 SaaS 有效目录。分别记录代码、部署、契约同步与真实验收结果。

## 授权说明与交接

公共查看、个人操作、业务管理是操作分类，不是自动授权规则。“个人操作”不代表自动获得权限。新应用、带策略新增操作、旧资源继承应分别核对 SaaS 当前实现与保存结果；不得承诺所有新增资源自动继承或全部需要重授。管理员撤销、停用优先，不借升级恢复权限。

企业专属模块清单和映射保存在对应项目交接记录，不写入通用 Skill。尚未适配的系统要注明仍可能出现重复导航；Skill 下载成功不是子系统升级成功。
