# 备份覆盖与恢复验收

本页用于企业服务器初始化、备份故障、数据丢失、机外保护及管理员恢复点接入。备份与恢复由企业服务器和业务系统执行，SaaS 汇总受控证据，Skill 约束开发与验收。平台主服务器及独立项目由「灼见服务器部署」Skill 的既有主机发布和备份机制承接；不为复用本页而重建企业 Runtime。

## 先确认真正需要恢复的内容

- 按当前 Runtime 登记、运行 release、容器实际挂载、数据库连接位置和真实文件引用列出系统清单；不能仅搜索名为 `data` 的目录。数据库可能位于容器可写层、应用工作目录、独立数据库服务或外部源。
- 每系统分别核对数据库、本地文件、OSS 附件、源码/Git、必要配置及实际运行版本；明确内网 NAS/ERP 原件、缓存和引用的边界。外部原件留在企业内网的约定继续有效，不暗中复制整套原件。
- 归档记录原数据库和文件恢复目标、运行提交、镜像引用、必要启动布局和受保护配置。服务器本地 Git 是源码工作真源，但同机 Git 不构成机外副本。未提交工作区与已提交 Git 历史分别交接。
- 无数据库或文件须由实际盘点证明；没有采集到不能记为零或不适用。共享数据库、共享对象目录与主机整包必须显式标为共享，不能按项目数平均分容量或猜测所有权。

## 保持线上使用的一致性备份

平台预绑定与企业 root 接入按 [Runtime 存储初始化](runtime-storage-bootstrap.md) 执行。新启用自动保护的 Runtime，新系统成功部署后应自动登记已识别数据库与文件位置、启动该系统首次备份、机外完整回读和隔离恢复；本次运行提交的证明通过后才能通过首次登记保护验收。未识别数据库或缺少适配器，由开发 AI 在已有 root 维护权限内补齐并实测，不能让负责人准备云权限，也不能以 pending 冒充交付。其他系统的定时保护独立继续，旧有效点及已有上线业务保留。

保持线上使用是已确认约束时，不以恢复验收为由停止业务容器、重启主机、替换维护页或回写生产数据库。使用目标数据库官方支持的在线备份方法；SQLite 用 Online Backup API 处理实际在用库及 WAL，PostgreSQL 用一致性逻辑导出或经验证的物理备份。直接复制运行中的数据库文件或卷不自动等于一致性快照。

在线恢复包必须如实记录其方法和实际备份时间。不能为了通过旧上传器或导出器校验，把在线归档标成停写快照；扩展兼容前先验证新旧清单、机外链和恢复路径。若某种存储只能停写取得一致性点，保持旧服务并明确剩余依赖，不擅自打断线上。

本次快照中的数据库引用用于确定必须保护的附件。可变本地文件和未启用版本的 OSS 对象需要条件读取、前后稳定性检查或其他经验证方法；遇到并发删除、替换、release 变化或缺失引用，保留旧有效点，不能把不完整新点标为完整。不同系统/数据库的快照时刻分别记录，不承诺跨库原子一致性。

若源数据在备份前已经存在缺失附件，先只读查历史版本及旧备份。仍未找到时，保全数据库、现存文件、代码和配置，并以经过核实的缺失集合、摘要和计数约束部分恢复点；不能用通用忽略开关吞掉新增缺失。私有清单保留缺失来源，安全投影显示原有缺失数量及引用验证失败；实际恢复须从还原数据库重查。文件分项的字节校验通过，不代表缺失附件可恢复。其他系统仍独立备份，不因一项原有缺失阻断全部企业。

执行前估算归档、下载、回读、解包和数据库恢复的重叠峰值，核对真实文件系统与并发作业。逐系统串行验证，资源不足时排队或使用获权隔离节点；不删除旧有效点、生产文件或回退资产为测试腾空间。

## 机外副本与 OSS 附件

按 [机外备份与隔离恢复](runtime-backup-recovery.md) 复用独立私有备份范围，业务与备份身份分开。企业备份身份仅访问本企业当前环境；主服务器身份不能直接分发到企业服务器。按 [文件存储](object-storage.md) 保持现有业务桶、旧对象键和业务权限，备份接入不自动迁移业务文件。

普通数据库或 Runtime 归档不自动包含 OSS 正文。附件保护至少保存源对象身份/精确版本或稳定性依据、字节数、SHA-256、目标对象精确版本及独立私有清单；业务引用使用的历史版本亦需覆盖。删除标记和历史版本分别记录，不把同桶历史版本本身称为独立副本，也不将源删除同步为备份删除。

只有机外对象完整读回并匹配字节数/SHA-256，才记录机外已验证。HEAD、List、上传返回成功、定时器 enabled 和命令退出零都不能替代它。精确版本加摘要不等于 WORM；清理遵守已授权的保留策略，不能新增整桶统一删除规则。

机外清单必须能在原服务器丢失后由获权 Codex 按企业、环境、系统发现。原始归档、配置秘密、下载位置和凭据仅留受保护服务端，不进入浏览器、Git、日志或普通回复。

## 从机外版本进行隔离恢复

1. 取得明确恢复点，从其精确机外版本重新下载到独立受保护目录并验证摘要；不能只用本机尚存的原归档做机外恢复验收。
2. 在独立数据库、容器或目录实际恢复并读取数据库，检查完整性、必要表/约束和关键记录；数据库列表、归档目录或 SQL 语法检查不是还原。
3. 实际还原文件并逐项核对摘要；将恢复库中的附件引用与本恢复点的文件集合核对。Git bundle 要能独立克隆，运行提交及源码 refs 要可读取；必要配置和原目标映射要可解析。
4. 演练环境不得使用生产卷、生产数据库地址或业务外发身份。只读完整性验收不启动会发送通知、同步或回写外部源的恢复应用。需启动服务时使用独立网络/端口和受控测试配置。
5. 记录恢复点、演练时间、范围、结果、耗时及限制。数据库、本地文件、OSS、代码和配置分项报告；只验证文件时标文件范围，不能称整站恢复成功。恢复后生产切换仍需核对目标、最新数据及既有授权。

源码修复、Skill 发布、任务安装、首次真实备份、完整机外回读、隔离恢复和后续自动周期分别验收。未完成的项目保留待核实状态，不用上一份或另一个系统的演练覆盖本次声明。

## 管理员按企业和系统查看什么

SaaS 平台管理员的现有项目存储/备份恢复入口接入安全恢复点投影，不要求增加生产恢复按钮。每系统至少展示实际所属企业、环境、系统、最新任务状态、最近成功点、数据时间、覆盖分项、机外校验及隔离恢复结果。最近失败与最近有效成功点分别保存，失败不能把旧成功点抹掉。

每个来源保留自己的观察时间；聚合不能把读取旧文件的时间伪装成新观察。元数据只读投影可定时刷新，不能因此触发新备份、读取全部附件正文或执行恢复。来源断开、无证据、过期证据和实际失败须区分。

原始 URI、对象键、服务器路径、配置秘密和原始异常不进入前端。企业管理员入口若另行提供，后端必须按实际组织身份过滤；前端筛选不能代替租户授权。没有企业入口或生产恢复按钮不等于没有后台恢复能力，页面有绿色状态也不能替代恢复证据。

平台总库或主机整包覆盖多个企业/系统时，展示真实共享范围。库级恢复成功不能冒称已验证单企业选择性恢复；整机恢复与单企业恢复的影响范围须分别说明。

技术依据：[SQLite Online Backup API](https://www.sqlite.org/backup.html)、[PostgreSQL SQL Dump](https://www.postgresql.org/docs/current/backup-dump.html)、[OSS 前缀权限](https://help.aliyun.com/zh/oss/user-guide/access-control-base-on-ram-policy)。
