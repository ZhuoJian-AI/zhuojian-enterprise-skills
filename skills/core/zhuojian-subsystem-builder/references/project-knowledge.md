# 项目知识与接续

复用普通 Markdown、现有项目文档和中央交接目录即可，不要求安装额外知识库、向量数据库或后台采集器。知识帮助模型找事实，不替代现场检查、当前用户授权或运行时决策。

## 三类知识各有归属

- 通用 Skill：接入契约、工具、模板、可复用判断依据；从[知识索引](knowledge-index.md)按问题读取。
- 企业交接 Skill：某个企业/Runtime 的稳定事实，例如源码在哪里、实际发布方式、数据通道、既有兼容点。沿中央目录窄匹配分发，不把一家企业的例外变成所有企业的要求。
- 项目自身记录：当前运行版本、源码基线、数据和配置定位、未完成事项及验收证据。优先沿用现有 AGENTS、README、STATUS、docs/handoff，不新造另一套重复真源。

## 记录能影响后续判断的事实

在本次授权工作发现环境变化或完成交付时，由 AI 更新项目已有记录；稳定的企业事实变化，再同步对应交接资料。写清来源、观察日期和验证范围；源码已改、已运行、实际用户已验分别描述。不复制整段聊天、原始业务数据、账号密码或密钥；凭据仅保存受保护位置的引用。

旧故障快照供排查，不是永久现状。运行版本、权限或数据可能变化时按需核实；冲突时优先当前可验证事实，再修正原记录，保留必要恢复线索。公司专用资料如果只在某台开发电脑的本地 Wiki，不能宣称别人的 WorkBuddy/Codex 已经知道；需要可达的项目文档或正式匹配的交接包。

维护交接与本次变化相称；只读查询无新事实不制造修改，不要求每次小改重建全库。中央发布和客户端安装/加载分别记录，发布不等于当前聊天热刷新。
