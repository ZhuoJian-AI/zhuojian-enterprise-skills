# 工作空间与业务授权边界

员工只归属一个部门，角色可以多个。两者不是互相替代：部门确定组织归属，角色追加能力。

- SaaS 企业公共空间及员工当前所属部门空间默认允许查看、下载。其他部门空间须由角色追加访问；历史 `departmentIds` 和业务数据范围不是工作空间授权。
- 默认只读不包含上传、修改、删除。部门上传／修改与删除分别授权，旧上传授权不会自动增加删除；企业公共空间管理沿用其明确管理权限。多个角色按具体操作取并集。
- 个人空间只属于本人；企业隔离、资源停用和删除仍优先。调部门、撤销角色后应重新取得 SaaS 有效权限，不延用缓存或旧会话。
- 子系统页面与公共查看、个人操作、业务管理、旧版 Action 仍按原契约和角色鉴权。工作空间默认可读不意味着个人 Action 自动授权，也不意味着业务记录变成公开数据。
- SaaS 负责工作空间目录、文件读写、预览下载和最终 Artifact 提交；业务子系统继续负责业务记录归属、状态、范围及签名身份检查。不能因为“鉴权在 SaaS”就删掉子系统服务端校验。
- 导出仍返回获权结构化数据，由 SaaS 写入有创建权限的目标空间。能下载目标空间文件不代表能向其保存新文件。

这次工作空间规则更新不要求合规子系统改契约、改数据库或重新部署。Skill 更新本身也不会修改 SaaS：旧部署或能力不明时读取实际有效权限，不能仅凭本文件或用户部门字段在子系统自行放行。
