# 工作空间与业务授权边界

员工账号所属部门 D0 是默认工作位置，角色可以不追加部门，也可以追加多个部门；员工可绑定多个角色。工作空间与企业模块权限可分别编辑，不设“先选部门才能勾模块”的串行门槛。

## 工作位置与操作分别计算

- 工作位置展示取当前同企业存活 D0 与所有有效角色追加部门的并集，去重；D0 来自账号绑定，不让管理员在每个角色重复勾选，也不通过角色改写员工组织归属。无 D0 的员工仍可获授个人、企业共享或语音能力。
- 部门业务 Action 只取独立授予同一企业/应用/模块/页面/Action 的有效角色；对每个授予角色先计算 D0 加该角色追加部门，再合并。例：D0=A，查询角色追加B，导出角色追加C，则查询A/B、导出A/C；不能拿工作位置总并集A/B/C用于每个操作。默认部门本身不授予Action。
- SaaS 在保存及实时解析时只接受当前同企业存活部门；未知、已删除、跨企业部门不得进入范围。无D0且无有效追加部门时，部门业务没有目标，不能回退all。停用/解绑角色、调部门、删除/移动部门、停用应用/Action后须重核旧会话、票据、确认与任务。
- 上述岗位工作范围须使用服务端明确支持的声明与解析，最终仍由实时session-check或Action JWT下发当前Action的effectiveDataScope。未部署支持时保留已核安全旧边界并列待适配，子系统不得从浏览器工作位置、用户departmentId或文案自行计算。

## 文件与其他业务边界

- SaaS 企业公共空间及员工当前所属部门空间默认允许查看、下载。其他部门空间须由角色追加访问；历史 `departmentIds` 和业务数据范围不是工作空间授权。
- 默认只读不包含上传、修改、删除。部门上传／修改与删除分别授权，旧上传授权不会自动增加删除；企业公共空间管理沿用其明确管理权限。多个角色按具体操作取并集。
- 文件与语音在统一模块目录勾选，但选择工作位置不等于勾选文件操作。个人、部门、企业文件的查看、下载、上传、修改、删除各自落实到实际入口；语音六项按平台能力鉴权，不要求角色选择部门。若保留不可撤销的基础能力，界面须锁定并显示默认来源；不可出现可取消的勾选被旧权限码或通配符继续放行。
- SaaS 角色 `platform_access` 按每个内置模块 key 迁移：某角色的某 key 已存在时，该角色对该模块只按明确的 enabled/action_keys 计算，不能再从该角色旧权限码或 `*` 恢复被取消的操作；部门文件范围只配对同一角色的工作位置，语音不要求部门。其他有效角色仍按各自已核授权参与逐操作并集，尚未迁移的其他 key 保持已核旧语义，不能把单模块迁移当作全平台切换。已迁移 key 不得删除，取消授权须保留 key 并关闭模块／取消操作；整体配置不得置 null 退回旧模式。`workspace_access` 非 null 后也不得用清空字段恢复旧范围；个人 owner、企业公共和 D0 的基础查看／下载仍独立保留并显示其来源。
- 个人空间只属于本人；企业隔离、资源停用和删除仍优先。调部门、撤销角色后应重新取得 SaaS 有效权限，不延用缓存或旧会话。
- 子系统页面与公共查看、个人操作、业务管理、旧版 Action 仍按原契约和角色鉴权。工作空间默认可读不意味着个人 Action 自动授权，也不意味着业务记录变成公开数据。
- SaaS 负责工作空间目录、文件读写、预览下载和最终 Artifact 提交；业务子系统继续负责业务记录归属、状态、范围及签名身份检查。不能因为“鉴权在 SaaS”就删掉子系统服务端校验。
- 查看与下载是两个许可。复制文件、归档打包、原件派生、原始字节／Base64 响应、原件预览或下载签票，以及 MCP 等外部宿主取得下载票据，都必须重核源文件 download；写入新文件还须核对目标空间 create。不能借“已可查看”、旧票据、文件 ID 或服务端代签绕过下载撤权。仅查看元数据、解析所得文本或受控解析结果沿用 read/query，不得因为没有 download 就一并拒绝获权的解析文本读取。
- 导出仍返回获权结构化数据，由 SaaS 写入有创建权限的目标空间。能下载目标空间文件不代表能向其保存新文件。
- 企业共享业务、固定个人owner、NAS敏感目录与通知接收部门分别保留原有真实边界。部门文件空间、公司共享盘目录与业务记录不是同一资源，不能统一套部门过滤。已签发OSS下载URL可能有受限有效窗口，不能承诺撤权能追回已发链接或已下载字节。

逐系统核对归属字段与实际入口：已正确消费精确Action实时范围且业务边界未变的系统无需重写业务；仅声明变化走元数据兼容验收；缺部门归属或新增/修改混用的系统须适配并单独部署。Skill更新不会修改SaaS、角色或现有子系统，也不代表运行时已修复。

`workspace_access/platform_access` 保存后的完整运行时语义下限为 `role-workspaces-v1`，不能把只补 `0084_role_workspaces` schema 的桥接镜像当作授权回退目标。仅恢复旧 Manifest、删除逐模块 key、置 null 或降库都可能复活旧通配授权；完整授权逆迁移未经审查和验证前，全部消费端及恢复目标必须保留该语义。具体证据和反向顺序见[元数据发布与回退顺序](action-permission-scopes.md#元数据发布与回退顺序)，能力标记不能替代真实代码与允许／拒绝／撤权验收。
