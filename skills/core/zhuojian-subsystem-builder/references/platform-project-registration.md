# 平台项目归属与入口验收

新系统首次上线，或获授权修改现有系统归属、域名、管理入口时必读。交付结果包括正确企业归属、已生效登记、真实业务入口及实际授权；已有业务管理页面须接好对应入口。企业开发AI通过既有Runtime和已获权员工会话完成，不需要取得SaaS平台管理员会话。平台管理员目录的公共显示与管理入口回归由SaaS维护测试承担，不作为每次企业发布的人为前置步骤。普通局部维护只检查受影响入口，不借本规则批量迁移旧系统。

## 先按实际归属选择路径

| 类型 | 登记与显示位置 | 身份与管理入口 |
| --- | --- | --- |
| SaaS 某企业的子系统 | 使用已核对的企业、Runtime、applicationSlug，通过 Runtime 登记企业应用及 Manifest；在平台管理员端“企业与项目 → SaaS 企业 → 所属企业”的应用中核对。子模块仍在该应用内。 | 员工与企业管理员沿用 SaaS 统一身份、有效角色和记录范围；平台管理员使用平台已支持的授权管理入口，不能借某企业员工身份或扩大角色权限。 |
| 独立项目或平台服务 | 按“灼见服务器部署”Skill 登记到平台管理员端“平台与独立项目”，包含稳定项目身份、名称、真实域名、实际服务器及管理入口。 | 项目原站账号/密码与平台管理员通道并行；免登录管理需要平台和项目共同实现受信授权。 |

企业子系统部署在独立 ECS、有独立域名或独立数据库，都不改变企业归属；不能因此在外层再造一个独立项目、企业或员工账号。独立项目也不能为了出现在列表而伪造企业/Runtime 绑定。分类证据取自实际登记与业务归属，不猜名称或域名。

本 Skill 承接企业子系统；识别为独立项目时转入服务器部署 Skill 的独立项目流程。企业应用登记、独立项目运营目录登记、发布器登记、Wiki 和模型网关项目登记各有用途，不能相互替代。不要给每个企业子系统写一份独立项目清单项，也不能让普通业务 AI 修改平台主机配置来伪装完成登记。

## 企业子系统的发布收尾

用户明确要求先接入但不开放权限时，首次调用 `publish_subsystem.py` 加 `--initial-access-policy disabled`。工具先核验鉴权的平台能力，缺少支持立即中止。新应用应为 `is_active=false`、`admin_disabled=true`、`assistant_enabled=false`、授权记录为零；系统开发者也不得自动获权。登记 healthy 表示契约健康，不表示已开放。重复同步保留持久策略，后续管理员显式开放须另有授权。已有普通应用不能借首次策略偷偷撤权，冲突须中止。验收期间不能为了打开页面而临时授权真实员工。

1. 保留已确认企业/Runtime/应用身份，按 [ECS 直接发布](direct-ecs-deployment.md) 完成真实版本、baseUrl、Manifest 和模块登记，确认平台接受并激活目标版本。
2. 使用当前Runtime的模块登记查询及真实支持的企业目录，核对企业/环境、应用身份、名称、模块、实际生效commit与baseUrl。保留脱敏读回证据；再用已获权员工身份验证实际入口。目录/接口的能力必须来自目标环境，不能虚构端点、导出管理员Token或借其他企业身份。Runtime healthy只能证明登记，不代替员工业务验收。
3. 平台中展示真实可点击域名。实际打开后到达正确原网站，HTTPS、原路由和当前鉴权正常；需要 SaaS 登录时走已有登录/SSO 流程，不能为了“能点开”放开匿名业务访问。域名变更保留任务要求的旧入口并分别验证。
4. 系统已有业务管理页面时，登记稳定且权限正确的管理页面/模块，并用企业内已有获权身份完成该业务入口验收。企业业务操作继续校验角色和记录范围；root开发身份不冒充员工业务身份。平台管理员专属管理入口若本次涉及其实现，单独列为SaaS交付项，不能因此阻止已获权的企业开发/发布。确实没有管理后台则明确记录“无管理后台”，不造空入口。
5. 对本次新增或修改的业务页面，分别验收桌面和手机的入口、返回、实际业务和登录/撤权边界，保存页面证据并明确模拟与真机范围。仅配置现有后端关系不强制浏览管理界面。未接好的业务入口标为待完成；未访问的平台管理页面不记为已验收，也不将普通业务入口称作已完成平台管理员免登录。

发布授权包含本次必要的登记与入口验收；在已有权限和能力范围内继续完成，不再逐项索要批准。SaaS维护方负责公共目录、平台身份与平台管理入口，企业开发AI负责真实业务入口和服务端鉴权。若已有Runtime能力足够，不以缺少平台管理员会话为阻点；真实缺失的公共能力、员工权限或业务入口分别记录具体缺项与责任层。AI继续完成可独立推进部分，不让负责人提供平台Token、自行设计接口或逐项点管理页面。员工角色新增不由服务器root冒充授权，使用已有企业授权流程。

## 原网站与原密码的兼容边界

独立项目已有的原网站、原管理密码及登录会话继续可用；新增平台管理员入口不能覆盖原凭证、共享密码或互相清除会话。平台通道退出、撤权或不可用不能破坏独立项目原站登录；新系统维护者按独立项目部署规则验收两个通道。

企业子系统仍遵守 [统一身份验收](identity-acceptance.md)：不为“原密码兼容”新增绕过 SaaS 的员工账号/角色或扩大既有访问。已有明确批准的兼容入口按原权限保持，记录与验证其范围；若接入统一身份需要改变现有登录行为，按该项授权完成迁移，不因本次目录登记顺带关闭原站或改密码。独立可访问的业务页仍需鉴权。

## 交付证据

交接记录系统类型、所属企业或独立项目身份、真实域名、平台内可定位路径、管理入口及访问方式、登记/发布版本、两端实点结果与未测项。有原站兼容要求时附原入口/原密码登录与平台通道并行验证的结果，凭据只通过既有授权入口使用，不写进文档或截图。Skill 更新仅规范后续交付，不代表任何现有系统已登记、管理入口已接通或已部署。
