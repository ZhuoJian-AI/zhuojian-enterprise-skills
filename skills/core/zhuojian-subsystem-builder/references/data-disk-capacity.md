# ECS 数据盘与容量迁移

本规则用于管理员处理附加云盘、系统盘告警、镜像仓库和构建目录占用。它不替代业务文件的 OSS 迁移，也不授权 AI 自动格式化磁盘、迁移数据库或清理未知 Docker 数据。

## 先只读确认

1. 列出块设备、分区、文件系统、UUID、标签、容量和挂载点，并用 `findmnt`、`df` 和文件系统签名交叉核对。设备名可能在重启或重新挂载后变化，不能只认 `/dev/vdb` 一类临时名称。
2. 盘点系统盘和已挂载数据盘的真实占用。Docker 使用 `docker system df -v` 辅助判断，但“可回收”不代表可以删除；再对已知目录和卷逐项计算容量。
3. 区分运行数据、数据库、业务附件、镜像仓库、构建产物、缓存、日志和回滚镜像。禁止把未知卷、停止容器的卷或悬空卷直接认定为垃圾。
4. 检查当前是否有发布、构建、镜像推送/拉取、备份、同步或业务写入。写操作仍在进行时只允许做第一轮只读复制，不执行切换。

## 初始化边界

- 已有文件系统、分区、签名或挂载记录的设备一律视为可能含数据，不得重新格式化。
- 只有用户明确授权初始化，并且设备路径、容量、云盘身份、无分区、无文件系统签名、未挂载全部核对一致后，才允许创建分区和文件系统。授权某台 ECS 不等于授权格式化其中所有空盘。
- 默认使用当前 Linux 已稳定支持的文件系统；没有项目特例时可使用单 GPT 分区和 ext4。设置可识别标签，使用 UUID 写入 `/etc/fstab`，修改前备份原文件。
- 挂载点必须是明确的新目录。不能把新文件系统直接挂到已有非空目录上遮住原数据；需要维持历史路径时，先挂到独立数据根，再使用受控绑定挂载。
- 更新挂载后运行 `systemctl daemon-reload`、`findmnt --verify` 和 `mount -a`。关键服务应依赖真实数据盘路径并在磁盘缺失时失败关闭，不能悄悄回退到系统盘空目录继续写入。

## 放置优先级

优先把容量大、可验证且与在线数据库解耦的内容移到数据盘：

1. 私有镜像仓库数据；
2. 构建包、构建工作目录和可再生成缓存；
3. Runtime 管理的本地应用文件与备份，但必须逐应用停写、校验和回滚；
4. 数据库或整个 Docker 数据根只允许在独立停机迁移计划中处理，本规则不自动执行。

保留应用看到的稳定路径，例如 `/srv/zhuojian/data`。物理设备和挂载根属于宿主机部署信息，不写入业务源码、Manifest 或用户回复。挂载数据盘仍是 `local-managed`，不能替代 OSS 的对象隔离、临时身份、版本保护和异地恢复策略。

## 双阶段迁移

1. 在目标盘创建精确目录并保留所有权、权限、硬链接、ACL 和扩展属性。写入服务仍运行时先做第一轮复制，减少最终停顿。
2. 第一轮完成后比较源与目标的总字节、文件数和关键目录；只读验证通过后，停止唯一写入者。运行中的业务服务不依赖该写入者时不必连带停止。
3. 做最终增量复制并再次比较字节、文件数和同步差异。任何差异、目标盘空间不足或来源不明确都要恢复写入者并取消切换。
4. 使用绑定挂载或带明确设备目录的 Docker local volume 保持原稳定路径。复制容器原有镜像、端口、网络、重启策略和只读配置，不凭记忆重建。
5. 原数据先移动到同一文件系统上的精确隔离目录，不在 Docker 将要删除的卷目录内部保存回滚副本。新服务、挂载和读取验证通过前不得删除旧副本。

## 验收与清理

- Registry 至少验证 `/v2/`、仓库目录或标签读取，并确认使用的新卷实际指向数据盘；构建目录要验证从 `/etc/fstab` 重挂载后仍能读取。
- 检查全部受影响容器、公开健康接口、当前运行版本和必要只读功能。迁移存储不应顺带触发应用版本更新。
- 记录系统盘和数据盘迁移前后占用、设备 UUID、稳定挂载点、迁移目录、暂停范围和验证结果；回复业务用户时不暴露内部路径。
- 只有精确源/目标再校验一致、服务恢复且持久挂载验证通过后，才删除旧副本。删除前解析绝对路径并确认它位于预定隔离目录，禁止全局 `docker system prune`、`docker volume prune` 或对数据根递归清空。
- 回滚时先停止新写入者，撤销新绑定，恢复原卷或目录，再验证服务；结果未知时先查询当前挂载、容器和数据状态，不能重复迁移。
