# 企业插件研发入口

企业用户可有普通业务、系统研发者和管理员等多个有效角色。插件是接入通道，角色与精确工具授权由SaaS决定；Skill内容不授予权限，不要求业务开发者理解鉴权和部署实现。

## 使用当前真实能力

开发AI先核对本人企业和获权目录，按目标自主组合取数、资料、宿主代码环境及已提供的服务端开发工具。发现与调用都以服务端当前Schema为准，不把业务说明、角色名称或安装Skill当作能力已经实现的证据。

企业可将本Skill正文、引用文档和文本模板通过已授权说明工具交给AI读取；不要求MCP resources接口，也不要求开发者先取得root才能读取开发说明。企业特例由匹配的交接Skill提供，不写入通用Skill。文档读取只返回包内参考内容，不接受任意服务器路径或返回凭据。

## 角色与操作

受管子系统目前为系统研发者维护完整已登记操作的托管授权。带明确permissionPolicy的新Action不从普通业务角色的应用级权限自动继承；仍需核对该环境的实际授权记录、启停和数据范围。企业管理员负责配置授权，管理身份本身不能代替某项业务授权。

数据查询保持数据源服务的实际权限，例如ERP专用只读身份。新增业务系统的员工权限仍由该系统服务端实现，不因开发者能取原始数据就向所有员工开放。身份、企业、工具、资源、授权版本及结果归属由对应服务保证，不增加DLP/PII扫描、内容审查或任意业务步骤门禁。

## 开发执行与交付

推理由宿主原有AI负责，不新增服务端业务决策主脑。宿主可在其已授权本机环境读写代码、计算、测试和生成预览。只有真实服务端文件、命令、依赖、构建、观察和部署工具已提供并验证时，才报告可以通过插件在服务器完整开发。

当次只有数据/资料工具时，先完成真实取数、口径核对和可独立完成的本地开发，不冒充已部署；服务器执行缺口必须明确。已有独立SSH开发授权时，可按原访问登记使用企业服务器，不将root或密码放入插件，不以SSH冒充被拒绝的员工调用。未获服务器执行能力时不伪造命令成功或要求业务负责人代做终端操作。

产品界面、SSO、权限、文件、备份和发布继续执行本Skill对应契约。按本次实际链路验证研发角色允许、普通角色拒绝、撤权、错误/文件回传及最终业务结果；真实员工客户端、合成身份、宿主本地与服务器验收分别报告。
