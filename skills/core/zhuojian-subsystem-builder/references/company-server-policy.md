# 企业单服务器与多项目

## 部署规则

一家公司使用一台正式业务 ECS、一个现役 Runtime，承载该公司的多个项目／子系统。新增部门、模块、独立域名、数据库或发布周期不构成另开服务器的理由。先扩展现有系统；确需新的 `applicationSlug` 时，仍部署到同一公司的这台业务服务器。

开始选址或初始化前，核对平台企业／Runtime 登记、已安装的企业交接 Skill、服务器访问记忆和目标主机的非敏感 `/etc/zhuojian/runtime.json`。公司名称只作核对，不能据此创建新企业或替换真实 `enterpriseKey`／`runtimeId`。已有业务服务器且已初始化时直接复用；确无已登记业务服务器时，才按管理员模式首次接入一台。

历史企业有多台主机时，继续如实登记每台的当前 IP、Runtime 和项目；本规则不代表已合并。维护已有项目仍沿用其当前主机。新项目若尚无明确指定的承载主机，先明确归并目标，再实施；不得随机选一台、另开第三台，或只改登记假装迁移完成。实际归并另按 [跨主机与跨地域迁移](region-migration.md) 规划并获得相应迁移授权。

## 同机项目边界

- 各项目保留自己的 `applicationSlug`、容器／网络、域名、回环端口、数据目录、数据库或独立 Schema 与访问凭证，不因共机合并业务数据、扩大权限或共用项目密钥。
- 每个项目独立检查健康、发布、回退和备份；只操作目标项目，保留其他项目及数据。核对 CPU、内存、磁盘和构建并发，使用 Runtime 实际支持的限制，避免一个项目的构建或发布耗尽整机资源。
- 同机隔离是项目与进程边界，宿主机故障和重启仍会影响同机项目，不能承诺绝对互不影响。独立域名／数据库／容器不表示独占服务器。

容量不足时先核对使用量、构建位置和现有 ECS 的规格／磁盘升级方案；需要换机时整体接管到一台替代主机，源端只按迁移计划暂时保留。不得自行用第二台长期业务服务器扩容；扩容、购买和迁移仍按该任务已获授权的范围执行。

## 平台与登记

SaaS 公共平台、统一模型网关、对象存储和 CI 构建执行位置是共享能力，不要求为每家公司复制到业务 ECS，也不计作该公司新增的业务服务器。子系统继续委托 SaaS 登录、授权和模型能力，不分发平台或模型密钥。

项目类型仍按真实身份／归属契约判断：企业 SaaS 子系统走企业应用登记，独立项目走服务器部署 Skill；同一客户的多个独立项目也复用其已指定业务服务器，不能因为分类不同就重复开机。

新增、接管或迁移后如实维护企业、现役主机、Runtime、项目、域名和有日期的状态，并同步部署 Skill 的中央台账。规则发布不修改 Runtime／平台的注册能力，不阻断现有多机服务，也不自动迁移或退役任何服务器。
