# 接入与界面结果参考

本页保存按需查询的细节，不是每轮必读清单。按本次影响选择相关章节；既有线上协议和服务授权继续有效。工具使用顺序、修复办法和验证范围由 AI 根据目标与实际反馈决定。

## 前端交互默认

- 使用原生鼠标光标，默认不加入 React Bits TargetCursor、四角方框或鼠标跟随装饰；新增此类效果须由用户明确指定。
- 导航与入口卡片使用静态正面，电脑单击、手机单次轻触、键盘激活直接进入，不以翻面或再次点击作为进入步骤；保留简洁的悬停、选中和可见焦点反馈。
- 保留已确认的图片、丝带背景和业务规则。AI 语义锚点操作提示仍按原 Bridge 契约实现，不跟随用户鼠标；不得把本条当作删除业务提示或必要写入确认的依据。范围与双端验收见 [全端界面](platform-contract.md#电脑平板和手机全端界面)。



开发 Codex 的企业服务器维护身份、经 OAuth 接入的员工宿主、浏览器业务助手分别判断。后两者复用 SaaS 当前员工授权、业务确认、审计与子系统服务；开发 Codex 在已确认范围内使用企业 root 完成接口、机器委托、迁移和发布，不受该员工的工具目录限制，也不把 root 转交线上助手。确定性队列、同步与重试可在企业服务实现；若需要 SaaS 助手离线自主推理或代员工运行，才核实对应平台支持及独立委托。不同员工、租户和宿主不共享会话历史。

涉及员工 OAuth 宿主接入、新增或变更面向 AI 的 Action、其发现目录或工作空间文件交付时，读取 [企业插件与外部宿主接入](external-agent-access.md)。插件通用，企业与员工由 SaaS 授权服务绑定；稳定发现/调用入口每次读取最新获权目录，Schema 摘要过期须拒绝并重新发现。业务 Wiki 只作背景，客户端工具批准不替代业务确认；不向员工插件下发 SSH/root，不承诺所有客户端即时热刷新，也不因插件接入关闭浏览器助手。企业服务间文件传递按 [企业服务器内业务服务对接](intra-enterprise-service-integration.md) 实现。

涉及角色、公共内容、个人或部门记录时，读取 [操作权限与记录归属](action-permission-scopes.md) 和 [工作空间与业务授权边界](workspace-access.md)。管理员只勾选能力；账号所属部门默认加入，角色只追加工作部门，工作空间与模块可分别编辑。具体部门Action只合并独立授予该精确资源的同角色D0及追加部门；默认部门不自动授权。真实部门业务可显式声明 `permissionPolicy:{group:'management',mode:'workspaces'}`，不带范围选项；其他management新能力仍只含单项supportedScopes。不得把共享库、个人owner、NAS敏感目录、通知边界统一部门化，或从CRUD猜测范围。专用REST路由固定资源，导入新增/更新分别实时校验并保持原子性。源码、端点、登记和行为负例共同验收；旧2.4/2.5按精确基线兼容，新mode先部署所有SaaS消费者再登记，Skill更新不代表线上支持。

新建、接入旧系统或修改登录、权限、人员归属时，读取 [统一身份的入口核查与验收](identity-acceptance.md)。核查全部实际业务入口而不只看 Manifest；旧密码/接口不能绕过 SaaS，操作者与被选择人员分开，真实业务表单和遗留项必须闭环，技术预检不能代替业务验收。

修复手机钉钉、WebView 中“平台已登录，但业务页要求从 SaaS 打开”或 SSO 后仍返回 401 时，读取 [内嵌浏览器会话 Cookie](browser-session-cookies.md)。先核对换码、Cookie 签发与回传，再区分权限和会话传输；同站点兼容 Cookie 与原 Partitioned Cookie 引用同一服务端会话，保留实时授权及迟到响应保护。多个子系统复用旧模板时逐个修复部署，Skill 更新不能代替线上修复或真机验收。

涉及员工选择、业务名单、账号绑定或历史身份修复时，同时读取 [员工目录与历史身份核查](employee-identity.md)。SaaS 稳定用户 ID 是员工身份来源，业务名单只管理参与、分组等业务状态；历史核查覆盖受影响名单及全部关联引用，不以局部修复代替完整核对。

涉及企业通知或向员工发送消息时，读取 [通用消息委托与通知业务边界](message-delivery.md)。业务草稿、页面和记录留在子系统；SaaS 只提供目录、逐 Action 授权、可信确认、投递与回执，沿用原有角色授权入口。

涉及模块拆分、导航、模块导航主题或既有系统升级时，读取 [模块导航与安全迁移](module-navigation-migration.md)，按服务器当前契约生成新旧映射和权限影响。SaaS 提供系统导航、桌面横向模块导航及手机自动换行模块网格；手机不能要求左右滑动才能看全八个模块。嵌入页面隐藏重复导航，保留紧凑业务内容；SaaS 以当前系统主题衔接其模块栏、标题身份区和侧栏选中项，并允许平台导航轨、通用操作及同一统一助手的入口、外框与输入控件使用受控颜色，平台骨架、回答内容和审批语义状态仍保持中性，不把某个系统的风格套给其他系统。每个子系统发布前必须登记与自身页面配色一致、通过对比度校验的 `presentation.moduleNavigationTheme`；缺失或无效时 Skill 的源码、端点及登记前校验必须失败，不得报告“已同步”。只登记受控颜色，不开放 CSS；已上线旧版本仍由 SaaS 安全回退默认色，不因 Skill 更新停用。Skill 自动更新只更新开发规范，不代表业务系统已经适配、部署或同步。

手机平台模块导航必须首次默认展开；仅用户主动收放，切换模块不得自动收起。偏好由 SaaS 按企业与员工保存并同步同浏览器窗口；子系统提供稳定模块登记，不得重置平台选择。具体责任与验收见上述模块导航参考，登记完整的子系统无需为此重新部署。

涉及页面按钮跨模块/页面跳转时，同时读取 [标准导航 Bridge](navigation-bridge.md)。使用平台声明的可选能力和模板封装，不拼接 SaaS 内部路由、不访问父页面 DOM，不要求业务负责人取得 SaaS 服务器权限。隐藏外壳不能替代导航接口；独立入口仍需重新鉴权。

涉及业务页面把目标交给统一助手时，读取 [业务目标入口 Bridge](assistant-entry-bridge.md)，复用 `assistant-open.v1` 协商和模板适配器，只带入可编辑草稿，不自动发送、覆盖已有任务或代替确认。SaaS 与子系统可以在不同服务器；业务数据和执行留在子系统，平台通过签名 Action 调用，不共享数据库或模型密钥。没有协商支持就保留人工入口，不能凭本 Skill 宣称线上已实现。

涉及基于当前页面的真实检查结果主动提示员工时，读取 [当前页面的业务提示](assistant-page-suggestions.md)。协商 `assistant-suggestions.v1` 后只交接有界、可撤回的业务建议，由员工选择进入同一助手草稿；不监控全部点击、不启动后台 AI，也不强制每页都有建议。确定性检查和写入保护仍由子系统后端负责。

涉及让助手理解业务办理顺序、完成条件或主动提示员工时，读取 [业务流程知识、当前页与跨页检查](assistant-workflow-guidance.md)。开发 AI 从真实代码与业务话语提取可选 `workflowGuides`；有真实只读检查才登记 `proactiveCheck` 或独立的 `globalCheck`。前者仍仅在员工开启且当前页可见时查询；后者仅供已登录 SaaS 外壳在获权范围内跨页低频检查，不依赖当前页面、离线运行或自动启动助手。两者保持 2.4/2.5，不能把本地交付资料变成运行脚本；建议仍由员工选择进入同一助手，写入须重新授权与确认。

涉及 AI 在业务页面内显示操作位置、查询目标或跟随痕迹时，同时读取 [业务助手语义锚点 Bridge](assistant-presence-bridge.md)。每个 v2.5 AI 页面必须登记非空 `interactionAnchors` 与默认锚点，并让本页全部 AI Action 恰好映射到一个稳定锚点；业务 DOM 只暴露同名 `data-zhuojian-anchor`，由子系统适配器在自身文档内绘制只读光标和短状态。SaaS 只能发送已登记 `anchorKey`，不得发送选择器、坐标、DOM、CSS 或业务参数；不支持、缺失或过期时回退平台级伴随提示，完整文字说明始终保留。Skill 更新不代表现有子系统已经登记、部署或上线该能力。

涉及子系统发布、故障或健康提示时，读取 [子系统可用性与维护提示](subsystem-availability.md)。正常候选发布继续服务旧健康版本，不凭发布动作显示“正在升级”；计划维护、突发故障和 iframe/Bridge 未就绪必须区分。嵌入时由 SaaS 显示当前应用提示，独立入口由子系统显示；保留未保存输入，不自动重载或重试写入。此规则适用于新建和本次更新的子系统，不能只改文案不验证真实 `/health` 与业务写入边界。

- 员工从灼见 SaaS 登录，系统自己不再创建一套员工账号和角色。
- SaaS 组织结构只使用“企业 → 部门 → 用户”。企业公共及员工所属部门工作空间默认查看／下载，角色追加跨部门访问和写入；子系统页面、Action 与 AI 能力仍由有效角色授权，不因部门归属自动开放。实际访问以 SaaS 服务端有效权限为准；详见 [工作空间与业务授权边界](workspace-access.md)。不要创建 Team，也不要把子系统待办变成 SaaS 的跨部门待办。
- 企业管理员只需绑定“系统研发者”或配置业务角色；Runtime 更新不需要重复审核。多角色可以取并集，但每个页面和操作的数据范围必须单独计算，不能互相借权限。
- 页面按钮、SaaS AI 与获授权外部宿主调用同一套业务服务；修改、删除等高风险操作必须经过版本校验、业务确认和防重复执行。
- 系统文件统一经过模板存储层，当前可先用磁盘，以后可以按清单迁移 OSS。
- 浏览器助手基于业务数据生成文件时，走“子系统结构化数据 → SaaS 文件执行器 → 当前员工工作空间”链路；外部宿主可在自身环境处理获权数据，再通过平台受控上传、校验和提交交付工作空间文件。平台文件交付必须有真实文件版本回执与可用预览/下载，宿主本地文件不能冒充已写入工作空间；细则见外部宿主接入参考。
- 每个 AI 页面声明用途、核心实体、可回答问题、关联页面和 Action 语义；浏览器助手与外部宿主按各自本轮上下文发现当前获权工具，分类仅作检索提示，不作执行门禁。子系统不另建员工账号、助手会话或模型路由。
- OCR、语音转写、图片比较/分类、结构化抽取和业务预测等专业 AI 必须通过 SaaS 受控能力返回可校正草稿；人工确认后才调用普通 Action 写入业务记录，子系统不保存或直连模型供应商密钥。
- 前端必须交付**电脑端一套、手机端一套**界面方案，覆盖本次新建或修改的员工及业务管理页面，分别设计、实现、预览和验收；不能把电脑页缩小或隐藏关键功能作为手机交付。两端共享数据、权限、接口、业务逻辑和草稿状态，可复用组件或按需拆分视图，不强制同一 DOM 或两个独立项目；平板和中间宽度保持可用。双端均须按实际容器宽高连续自适应，不能做成两张固定画布；验收增加窄窗口至超宽屏的连续采样、断点两侧、长内容及缩放后空间，不以几个固定尺寸截图代替。具体责任、预览与验收见 [电脑端与手机端双端交付](platform-contract.md#电脑平板和手机全端界面)。
- 手机适配必须用真实业务页面验证：至少在 Chromium、WebKit 的 320/390px 竖屏、844×390 横屏及桌面尺寸检查嵌入和独立入口，包括有数据的表格、模块内页面、弹窗、输入及返回。分别记录源码基线、页面覆盖、结果和未测项；静态检查通过、空白 iframe 样例或 `responsive_acceptance_pass: null` 都不算通过。浏览器模拟不能宣称苹果、华为、小米等真机已验收。局部滚动容器的网格父项也须允许收缩，不能用整页 `overflow:hidden` 掩盖裁切；窄屏不能直接隐藏关键业务指标。
- 新系统使用契约 `2.5`；已有 `2.4/2.5` 系统的普通维护保持原版本。`2.4 → 2.5` 只在用户明确要求迁移时执行。登录、权限和平台接入的技术细节由模板、Runtime 与 [平台接入协议](platform-contract.md) 自动落实，不转嫁给业务用户。
