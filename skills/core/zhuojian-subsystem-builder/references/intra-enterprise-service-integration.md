# 企业服务器内业务服务对接

适用于同一企业、开发 AI 已获权维护参与项目的服务协同。默认企业负责人只掌握本企业服务器；业务解析、保存、队列、文件交付和结果查询在企业项目实现。SaaS 提供统一登录、员工权限、应用登记和通用助手等公共能力。业务流不需要模型时直接实现确定性服务，不因缺少平台事件、跨应用文件或后台助手特性而等待平台开通。

本页规定开发和验收方法，不提供现成 SaaS 接口、通用服务密钥或自动业务授权。接口名称、网络地址和载荷由 AI 按当前项目真实代码实现并记录，不向不存在的接口发送请求。

## 开发权限与线上执行身份

- 业务负责人已确认参与系统、操作、数据和最终结果，且开发环境持有这些项目的受信 root 时，AI 可自行改代码、配置专用服务身份、编写迁移、合并、按已有发布授权部署并验收。没有现成业务接口是待开发工作，不等于开发 AI 无权实现。相同范围的确认复用，不要求负责人批准每条技术命令，也不索要 SaaS 主服务器 root。
- 开发 Codex 与员工使用的浏览器助手、OAuth 插件不是同一身份。员工工具被拒绝后不得 SSH 兜底的规则不收窄已获权开发维护工作；开发 root 也不作为线上员工身份或通用业务 Token 下发。
- 员工发起入口继续核验当前有效的员工身份、页面/Action 与本业务操作权限。目标服务对机器调用核验企业负责人明确授权的业务委托；若所选方案是代理员工执行，则还必须核验该员工的当前目标操作权限。机器委托使用自己的执行主体，来源员工只作为可信来源与审计关联，不能伪造其拥有目标全部权限。
- 权威应用仍负责自己的数据、业务规则和操作限制。另一应用调用它的业务服务，不直接写它的数据库；原来只允许审批人完成的审批等规则不因联通而取消。新增参与者、超出已确认操作或跨企业范围才需要确认相应差异。

## 从现有项目落地

1. 在当前 AI 的连接中执行 `whoami`、`id`；非 root 时用 `sudo -n id` 检查既有免交互提权。核对 Runtime 企业身份、参与项目、实际运行提交、AGENTS/TASKS、Manifest、鉴权及解析/保存/查询服务，建立独立任务 worktree。另一 AI 的 root 测试不能证明本连接有权；网络失败、SSH 拒绝和可登录但不可维护分别报告。
2. 保存业务范围与关系清单，明确唯一权威记录、允许操作、发起者、字段/文件、失败处理和完成条件；已有同范围确认直接引用。按下节迁移已被当前授权纠正的旧项目规则及阻塞待办，不把旧技术选型当成新的审批要求。
3. 复用目标已有解析、校验、保存和查询函数，补齐真正缺少的专用服务入口及来源入口适配。同步处理直接返回真实结果；耗时处理保存任务/队列并提供结果查询。页面、AI Action 和企业服务入口共用同一业务实现，不复制另一套解析保存逻辑。
4. 配置并验证下面的服务身份、文件传输和幂等结果。使用本企业私网、受控回环代理或适合现有部署的本机服务通道，固定绑定目标；客户端不能任意指定 URL、目标企业、服务或操作。不要为了服务互通把全部应用加入存储私网、挂载彼此整个数据目录，或公开无鉴权业务端口。
5. 备份数据/配置，按固定 Git 提交和当前线上基线部署受影响项目，核对旧入口及新链路。普通确定性队列、回执查询和幂等重试由企业服务运行，不以开发 Codex 常驻或定时发聊天代替处理，也不冒称实现了离线自主 AI 助手。

## 旧项目规则与阻塞待办迁移

更新 Skill 不改写现有项目。读取当前分支和实际运行版本中的 AGENTS、TASKS、交接及对接待办，找出“跨模块只能事件”“必须平台先开通跨应用文件接口”等与当前明确业务授权冲突的前提。保留 Git 基线，仅按已确认范围在原文件修正技术约束、标明被替代的判断及实测依据；同一任务的后续步骤改为企业服务实现，不另写一个新文件让旧阻点继续生效。

只迁移已被用户当前授权明确纠正的架构约束；企业隔离、员工撤权、业务资格、危险操作确认及数据归属继续保留。旧待办保留历史和未完成状态，撤下已经证伪的平台依赖，不能把“无需平台新增接口”写成“业务已经完成”。各参与项目提交精确变更，交接关联新实现、测试和当前运行版本；其他任务的规则与未提交工作不覆盖。

## 专用机器委托

优先复用项目已有且适合该业务的服务身份；确需新增时，由开发 AI 在企业服务器创建独立、root 管理的身份并配置允许关系。最少绑定可信企业、来源应用/模块、目标应用/模块、操作和必要的数据/文件范围，以及有效性、停用/撤销和审计。允许同一服务身份承载明确的多条关系，不要求负责人按系统逐项操作；三四个或更多系统仍按整体范围维护各条关系与依赖。

凭据只在企业服务器受保护配置或现有 Secret 管理中生成和注入相应服务，留给后续 Codex 的是配置引用及轮换/撤销方法，不是明文。不得复用 SaaS 的 Manifest、SSO、Action、Event 四类凭据、其他应用文件令牌或平台全局密钥；专用机器签名也不能伪装成 SaaS Action/Event JWT。企业 AI 负责实现和验证该契约，不能把一个新配置文件当成已有 Runtime 或 SaaS 已消费的授权。

提交、原件读取、结果查询及恢复均验证当前服务身份、允许关系、企业/应用/操作与必要数据范围，并检查请求完整性、有效期和重放约束。原始员工身份由来源已鉴权后端取得并绑定，不能接受浏览器自报 actor/role。员工查看结果仍核对其当前权限及提交归属；代理员工执行的延迟任务在执行/恢复时重新核对员工权限，明确机器委托按自身有效范围执行，不能偷偷切换这两种模式。配置停用或撤销后阻止新的机器操作；已合法提交的业务结果保留审计，不伪称可自动撤回。

## 文件原件与唯一存储

新上传优先由来源后端把原始字节流交给目标专用导入入口；目标经自己的存储适配层接收、核对字节数和 SHA-256，再调用权威解析/保存服务。沿用双方现有文件大小、类型、容量及超时限制，来源只保留业务允许的临时缓冲和提交凭据。要求“只保存在目标”时，来源不另存一份持久业务记录或永久附件。

处理来源已保存文件时，可实现专用读取委托，精确绑定文件稳定 ID/版本、摘要、目标服务、用途及有效范围，读取仍经过拥有该文件的服务及其存储适配层。不要把来源应用的长期存储令牌交给目标、复制原用户临时下载 URL，或让目标拼源应用目录/对象前缀。只有名称、版本号或 SHA-256 的事件摘要不等于已取得原件；受控流式推送和专用读取委托均需真实代码及授权负例。

传输途中中断或校验失败不生成完成回执。原件、解析产物和业务记录分别按已确认归属保存，清理来源临时文件须以可核对的目标结果及保留约定为依据。

## 幂等处理与最终回读

来源为一次逻辑提交保存稳定操作 ID，目标将它与来源身份、规范业务参数、文件版本/摘要和目标操作绑定。相同 ID/内容重试返回原处理结果，相同 ID 不同内容拒绝；目标的业务写入、任务状态及可重用结果保持事务一致。

目标结果至少能区分已受理、处理中、完成、失败和未知，并返回稳定任务/操作引用。完成时提供实际记录 ID/版本、必要的导入统计及错误项、文件内容摘要；来源通过真实同步响应、专用结果查询或明确回执关联到同一次提交。目标完成后来源应显示相同业务结果；仅 HTTP 200、已收件、队列存在或本地测试通过不能显示导入成功。

写请求响应丢失时先按原操作 ID 读回目标状态，核对已成功部分。后续重试遵循已实现的幂等契约，保留同一逻辑 ID，不换 ID 重做已经完成的写入。读回仍不能确定时保持未知；具体失败和恢复状态由服务保存，不能靠另一段聊天记住。

## 验收与接续

| 场景 | 真实证据 |
| --- | --- |
| 完整业务链 | 来源真实入口提交原件，目标核对同一字节/摘要并解析保存；目标记录/版本及来源最终显示相符，唯一权威存储满足确认范围 |
| 员工与机器权限 | 获权员工可从允许入口发起；无权员工、错误企业/应用/操作、伪造 actor、无效或撤销服务身份均不能写入或取得原件 |
| 重复、冲突与未知 | 重复同操作不增加记录；同 ID 换文件/参数拒绝；提交成功而响应丢失可从结果查询恢复，不重复成功写入 |
| 文件及业务失败 | 错版本、摘要、类型、容量或业务字段校验失败时保留真实未完成/失败状态，旧业务入口正常，临时文件按约定回收 |
| 多系统依赖 | 覆盖每个必需分支、汇合与最终结果；失败只阻断依赖它的步骤，恢复不重复已完成分支 |

新增或修改页面分别验收电脑和手机，接口验证与页面、模拟器与真机分开记录。交接保存真实接口/服务绑定、配置引用、操作/文件/结果标识、业务确认范围、源码与运行版本、备份、撤销/恢复方法和未测项；不存凭据正文。整体关系索引继续按 [多系统对接](multi-system-integration.md) 关联各项目证据，后续 AI 从服务器 Git、服务配置及结果记录接续。

只有所选实现确实需要的 SaaS 公共能力不存在或当前权限不可用时，才将对应平台依赖列为阻点。例如需要新的平台 SSO/员工授权或助手工作空间能力，却没有可用契约时，不能冒充已经实现；普通企业服务传文件和回读结果无需为此申请平台事件。缺权限、缺实现和未部署分别报告，并继续本企业已授权范围内可完成的工作。
