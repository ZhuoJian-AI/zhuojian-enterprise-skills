# 随研发交付业务角色

在实现业务系统时同步设计权限。沿用 Manifest 和 SaaS 员工账号，确定每种岗位可进入的页面、可执行的操作和可访问的数据范围。

1. 在 `modules[].accessRoles` 中定义业务岗位。为每种岗位分配稳定的 `roleKey`，列出模块实际声明的 `pageKeys` 和 `actionKeys`。分别处理查看、创建、审批、删除与导出。角色名称变更时保持原键。
2. 用 `permissionPolicy` 声明每项操作支持的数据范围。遇到既有系统，读取其生效的角色、人员与数据范围。按[员工授权](employee-authority.md)使用真实员工入口验证页面、操作、数据和撤权。
3. 用隔离演示用户测试最小权限。比如报表查看者可以打开门店报表并查看已授权数据，导出需要独立授予。记录模块、角色键、员工账号和验证结果。用员工账号或 ID 区分同名员工。
4. 在工作台核对项目是否已启用「业务角色与人员」。入口可用时，以当前获权项目负责人身份选择该系统角色和本企业员工，分配或撤销后核对员工视角。接入和委托状态以工作台为准。
5. 当前项目没有分配入口时，交付角色清单和已验证的权限矩阵，由企业管理员通过「业务角色与授权」配置。分别记录 Manifest 已验证、项目已接入、角色已生效及人员已分配的证据。

SaaS 实时核对项目和人员权限。研发 Skill 提供设计和操作说明，实际委托由企业管理员按项目授予。企业管理员身份、员工主档、工作空间、其他项目和原系统外部用户使用各自现有的授权流程。
