# 灼见企业子系统

把负责人的业务目标完成到实际可用。AI 根据现有系统、用户授权和真实执行结果，自主选择调查、实现、部署与验证方法；本 Skill 提供知识、工具和结果依据，不规定固定业务步骤。小范围修复按受影响范围处理，不要求重做整个项目。

## 工作方式

复用已有源码、运行服务、访问档案与发布方式。接到“没同步、看不到、不能导入”等描述时，结合实际用户入口和服务状态查找原因，不能只修本地代码或只相信此前聊天中的“已发布”。既有服务不因为目录、工具或权限与模板不同就视为未初始化；详见[现有系统定位](references/existing-system.md)。

负责人提供目标、业务规则和必要身份配合；AI 自行处理范围内的技术工作。已确认的授权继续有效，不让负责人转述命令、准备平台令牌或选择技术方案。缺少某一权限时，说明具体缺口并继续可完成的部分，不把权限不足当作系统不存在。Skill 本身不授予服务器或业务权限。

沿用宿主的推理与工具循环，根据观察修正方案；不增加第二个业务决策器、固定业务顺序、任意失败次数、失败后移除仍获权工具、关键词门禁或重复审批。身份、租户、业务授权、协议完整性和执行幂等由对应服务负责；不额外加入 DLP、PII 扫描、内容风险评分或同类内容审查。

## 按需查知识

[知识索引](references/knowledge-index.md)按问题列出协议、工具和例子。先选与当前问题有关的条目，不要求把全部参考资料读完。企业特殊事实由匹配的交接 Skill 补充，项目里的运行与交付记录保存最新进展；两者的来源、日期及现场冲突处理见[项目知识与接续](references/project-knowledge.md)。

通常优先用已有 Runtime 身份匹配交接 Skill；档案暂不可读时，可用已核实的目标主机进行窄匹配，不猜企业、不绕过权限。命令与兼容情况见[企业交接 Skill](references/managed-handoff-skills.md)。交接资料是有日期的线索，现场证据优先，不能拿旧快照覆盖新代码或数据。

## 更新与使用方式

本 Skill 从企业网页“系统研发”独立安装，普通员工业务插件不包含研发资源；保留已有独立 Skill、SSH 档案和登录。[独立 Skill 与研发通道](references/plugin-development.md)说明 SSH 和可选插件研发的区别。

调用时沿用现有稳定更新机制，各检查一次：

```text
python <skill>/scripts/update_skill.py
python <skill>/scripts/update_managed_skills.py --skills-dir <当前Skill的父目录> installed
```

AI 自行替换实际路径；WorkBuddy 等宿主沿用当前 Skill 的真实安装父目录，不默认写入另一宿主。更新后读取新版入口与本次需要的资料；网络失败可继续使用本地版本。`installed` 只检查已安装交接，不代表目标企业已经匹配；首次匹配使用 `resolve`。详见[稳定更新](references/skill-updates.md)。更新不是后台推送，不承诺当前聊天即时热刷新，也不部署业务系统。

## 结果与边界

用户要求实现并上线时，任务包含范围内的修复、部署、平台同步及实际使用验证，由 AI 持续处理。用户只要求审查、讨论或明确暂停时，按其范围执行。验证方法随变化选择；契约校验、健康检查和真实员工业务结果各说明证明了什么，未测或受阻部分如实记录。源码修改、发布成功、平台同步、本人可用分别有证据，避免部分完成就宣称全好。

SaaS 负责统一身份、公共外壳和通用助手；子系统负责业务页面、数据与操作；Skill 负责知识、接入工具与交接。维护保留已支持的 2.4/2.5 契约及真实业务权限，新系统默认 2.5；Skill 升级不自动迁移系统、重发旧应用或扩大角色。影响持久数据的工作复用实际备份与恢复条件，普通样式修复不要求全量备份或新增云服务。具体协议和双端界面要求按知识索引读取。

企业员工、合作方和个人用户分别表达。原系统登记的可登录用户可通过[应用用户与平台身份](references/application-users.md)关联到 SaaS，无需先成为企业员工；只出现在业务文本中的联系人不必开户。原账号、角色、登录页和历史归属保持，平台登记与业务授权分别说明。

企业员工从 SaaS 获授角色后，按该角色的页面、操作和数据范围使用业务，不再人工加子系统员工白名单。原企业软件、SaaS 和业务系统可以保留各自身份及旧入口；用已核实的稳定标识同步关联，原账号、角色、数据和归属继续保留。C 端/非员工可以有独立账号和白名单，不自动导入员工目录。具体边界见[员工授权与多方身份](references/employee-authority.md)。

Runtime 成功验证后自动登记生效，不等待管理员逐版本审核。新系统先只自动授权“系统研发者”，其他员工沿用真实业务角色和当前授权，管理员停用优先。

向负责人说明入口、实际完成的功能和仍待解决的问题；技术证据留在项目交接。不要把服务器路径、Bucket、凭据或实现细节变成小白的操作任务。
