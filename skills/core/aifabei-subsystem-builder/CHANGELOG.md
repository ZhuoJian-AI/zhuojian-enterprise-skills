# 更新记录

## 1.1.0 - 2026-09-11

- 新增唯一企业 Skills 总仓库目录；业务负责人仍只需首次提供服务器 `IP + root + 密码`，无需回答人员身份、创建 GitHub 仓库或手工选择交接包。
- 登录已初始化的 ECS 后，以服务器 `enterpriseKey + runtimeId` 为主、当前主机地址为兜底，自动安装或更新公司及服务器专属交接 Skill。
- 已安装交接 Skill 与总 Skill 分别保留独立 SemVer、更新记录和校验包；下载、路径、摘要或替换失败时保留旧版，跨主版本不自动升级。
- 本版本同时作为旧独立仓库到 `ZhuoJian-AI/zhuojian-enterprise-skills` 的同主版本桥接版本；接入契约继续使用 `2.5`。

## 1.0.9 - 2026-09-09

- 区分通用业务小助手与页面专业 AI：OCR、图片比较/分类、语音转写、结构化抽取和业务预测均由 SaaS 受控执行，子系统不保存或直连模型密钥。
- v2.5 Manifest 可声明严格的 `platformAiCapability` 草稿 Action；SaaS 重新校验员工、应用、页面、Action、输入和结果 Schema，并在权限变化时失败关闭。
- 原生模板增加专业 AI Bridge、可校正草稿、置信度、警告及人工确认流程；确认后才调用普通业务 Action，AI 结果不得自动写入业务数据。
- 源码、Schema 和端到端预检同步校验专业 AI 链路；预登记检查会明确标记真实员工 SaaS 专业 AI 验收尚未运行，避免将子系统端点自测冒充完整通过。
- 小白使用步骤未增加，接入契约继续使用 `2.5`。

## 1.0.8 - 2026-09-08

- 所有员工业务页面同时兼容电脑、平板和手机；同一套业务 DOM 连续响应，不新增第二套手机版或小白操作。
- 明确 SaaS 外壳与 iframe 子系统的响应式责任，覆盖触摸、键盘、软键盘、安全区、旋转、返回键、局部宽表格滚动和嵌入时隐藏重复导航。
- 原生模板补齐移动端安全布局；源码校验阻断缺失 viewport 和固定根最小宽度，真实浏览器回归覆盖八组视口及独立/嵌入模式。
- 接入契约继续使用 `2.5`；预登记技术检查明确标记真实员工 Chromium/WebKit/Firefox 全端验收仍需由 SaaS 执行，禁止把静态检查冒充浏览器通过。

## 1.0.7 - 2026-09-08

- Runtime 管理的 Manifest 通过校验后自动生效，不再要求管理员逐版本审核。
- 新应用自动授权内置“系统研发者”；既有业务角色只在原权限上限内继承新增资源，管理员拒绝与停用始终优先。
- 区分候选版本与生效版本，登记失败保留旧健康版本；事件声明不会自动创建投递路由。
- 小白使用步骤和接入契约版本保持不变，新系统仍使用契约 `2.5`。

## 1.0.6 - 2026-09-07

- 修复端点验收将 Manifest 契约 `2.5/2.4` 与错误的 `v2.5/v2.4` 凭证标识比较、导致合法 Runtime 凭证被误判的问题。
- 增加回归检查；不改变接入协议、不轮换凭证，也不增加小白操作步骤。

## 1.0.5 - 2026-09-07

- 每个 AI 页面声明精简的业务语义地图；SaaS 统一负责结构化意图、查询改写、页面关系、对话隔离和可信工具编排。
- v2.5 的 AI Action 使用封闭 Schema；查询和导出必须有界，导出只返回标准分页数据集，不生成服务器文件或虚假 Artifact。
- 端点与源码验收同步检查页面语义和工具契约；v2.4 继续按兼容规则维护，不被 Skill 更新隐式升级。
- 小白使用步骤没有增加；应用内历史对话、文件交付和完成判定均由 SaaS 自动处理。

## 1.0.4 - 2026-09-07

- 修改已有系统前先比较服务器、本地和远程 Git；服务器含有更新提交、分叉历史或未同步源码时，必须先从服务器建立开发基线，不能用落后副本覆盖。
- 同步时只保留经审查的项目源码，排除 Secret、数据库、用户文件、日志、缓存和构建产物；运行容器里的临时手改不冒充正式源码。
- 只有负责人明确指定其他权威版本，或服务器没有可验证源码仓库时才允许例外；本次不修改 SaaS 接入契约，新系统仍使用 `2.5`。

## 1.0.3 - 2026-09-07

- SaaS 组织和授权边界统一为“企业 → 部门 → 用户”，所有访问权限由用户绑定的平台角色取并集，不再创建或依赖 Team。
- 明确跨部门待办、审批和业务闭环属于子系统；无明确目标的事件只保留同步审计，不在 SaaS 隐式生成待办。
- Manifest Schema 与端点验收拒绝 Team 授权元数据；新系统的 SSO 与 Action 验收负载不再携带 `teamId`。
- 业务模式步骤、契约版本和用户所需输入保持不变，新系统仍使用契约 `2.5`。

## 1.0.2 - 2026-09-07

- 负责人首次提供服务器 IP、root 和密码后，即视为已授予当前 Codex 环境对该服务器的长期业务维护访问；后续不得再次向负责人索要账号密码。
- 首次密码登录成功后，AI 自动建立并验证该服务器专用的 SSH 密钥和本机访问档案；后续任务直接复用，密码不需要持久化。
- 长期访问失效时只报告需要企业管理员恢复服务器访问，不把云账号、控制台或新凭证要求转嫁给小白负责人。
- 本次没有修改 SaaS 接入契约；新系统仍使用 `2.5`，已有 `2.4`、`2.5` 系统继续按原版本维护。

## 1.0.1 - 2026-09-07

- Skill 自动更新成功后，AI 必须先读取本版本记录，再重新读取新版 `SKILL.md` 后继续任务。
- 稳定版压缩包必须包含与 `skillVersion` 完全匹配的有效更新记录；缺失或错配时拒绝安装和发布。
- 本次没有修改 SaaS 接入契约；新系统仍使用 `2.5`，已有 `2.4`、`2.5` 系统继续按原版本维护。

## 1.0.0 - 2026-09-07

- 首次提供公开 GitHub Release 稳定版自动更新。
- Skill 发布版本与 SaaS 接入契约版本分离，同一主版本内自动更新，跨主版本只提示管理员。
- 自动更新会验证版本、SHA-256、压缩包路径和必需文件，失败时保留本地版本继续工作。
