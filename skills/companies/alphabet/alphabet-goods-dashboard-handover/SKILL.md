# Alphabet 商品动销看板交接

本 Skill 是 `47.243.48.78` 上商品动销看板的交接层，必须与 `$zhuojian-subsystem-builder` 同时使用。总 Skill 负责服务器访问、开发、部署、统一登录、权限、文件存储和 SaaS 接入；本 Skill 只补充该看板的真实现状、业务口径和维护边界，不取代或放宽总契约。

本 Skill 由 `ZhuoJian-AI/zhuojian-enterprise-skills` 稳定目录托管。总 Skill 根据 ECS Runtime 档案或主机地址安装、更新本 Skill 后，立即重新读取本文件以及当前任务需要的 references，不使用更新前的交接事实。

## 面向负责人

当前用户可以只用日常业务语言提出问题。首次进入一个没有明确任务的对话时，简短说明可以直接要求 AI：

- 检查看板是否正常以及数据最后同步时间；
- 解释销量、库存、同比、环比和动销率等口径；
- 排查页面打不开、数据不更新或数字看起来不对；
- 修改筛选条件、指标、排行、页面和导出内容；
- 发布更新并检查电脑、平板和手机效果；
- 判断问题应由业务负责人处理，还是需要企业管理员调整平台角色。

用户已经提出明确任务时只用一句话确认能力，然后直接处理，不用介绍打断任务，也不要求用户选择技术方案或执行服务器命令。

## 交接前提

- 企业管理员已于 `2026-09-10` 完成 ECS 初始化和平台登记。普通任务使用 `$zhuojian-subsystem-builder` 的业务模式，禁止重复执行管理员初始化。
- 商品动销看板已经部署并接入灼见 SaaS。检查、修改或发布前读取 [系统现状](references/system-context.md)；其中是交接基线，回答“现在是否正常”前仍需实时验证。
- 只处理商品动销看板及其道讯只读数据链路。除非用户明确扩大范围，不改动同一服务器上的其他应用、数据库或服务。
- 交接时文件存储状态是 `local-managed`。出现上传或持久文件需求时按总 Skill 检查 Runtime 当前能力；没有完成迁移和验收前，不得宣称已经使用 OSS。

## 处理任务

1. 用户只问现状、原因或指标口径时，先做只读检查并直接给结论，不发布或修改配置。
2. 用户要求修改功能或修复问题时，先识别服务器上的真实源码和运行版本，保护线上基线与数据，再按 `$zhuojian-subsystem-builder` 完成修改、测试、部署、平台登记和健康检查。禁止用旧压缩包或落后 Git 副本覆盖线上代码。
3. 用户询问“数据截至某天”时，先核对销售截止口径和最近同步时间。销售默认取当天之前最近一个完整周日，库存取同步时的实时快照；不要把正常的完整周口径误判为服务器故障。
4. 页面打不开时，依次检查公开入口、应用健康、平台权限、后台同步和内网隧道，并用“页面问题、权限问题、数据连接问题”等业务语言报告故障层级。
5. 调整指标、截止日期、筛选、展示或导出时，先复述预期业务效果，再直接实现并验证。只有会改变业务含义的歧义才向用户确认。
6. 员工看不到系统或业务数据时，先核对灼见 SaaS 角色。系统研发者的默认授权不等于普通员工已经获得业务角色；不得绕过数据权限制造可见结果。
7. 道讯链路保持只读。看板查询、统计和导出可以读取道讯数据；不得向道讯写入记录或用写语句测试权限。

## 连接服务器

只有任务确实需要检查线上状态、修改或发布时才读取 [服务器访问](references/server-access.md)。登录资料不由本 Skill 保存；优先复用总 Skill 建立的本机访问档案。访问档案不存在时按总 Skill 的首次接入规则处理，不向负责人索要阿里云、OSS、GitHub、平台或道讯令牌。

连接后先运行只读诊断并识别现有版本。删除应用或数据、清空数据库、覆盖线上基线、修改服务器密码、重建内网隧道、停用平台 Action 或重新初始化 ECS，必须得到用户对该具体动作的明确要求，并先采取可恢复措施。

若任务必须重新执行企业级初始化、修改平台级配置或分配员工角色，停止对应操作并说明需要企业管理员完成的事项；继续完成不依赖该权限的部分。

## 回复负责人

先说结果，再说明业务影响和需要负责人处理的下一步。完成变更时只报告系统入口、做成的功能、谁能使用、发布是否成功、健康状态、数据同步状态和文件存储状态；不展示凭证、服务器内部路径、对象存储信息或完整配置。
