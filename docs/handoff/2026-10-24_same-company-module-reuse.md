# 同企业单机多负责人：复用应用与模块

用户已确认场景为同一家公司多个业务负责人在同一台已初始化企业服务器上开发、对接多个应用或模块；其他公司使用各自服务器并由管理员初始化。本次只补正 core1.1.43 候选的默认业务流程，不实现多企业共用主机、负责人个人凭据或服务器迁移。

开发 AI 先核对实际应用/模块登记、业务对象和唯一存储，复用已有权威业务服务，按需要选择页面入口、获权 API/Action 或异步事件。服务器位置、部门或负责人不同，不单独决定增加应用或事件路由；整套应用合并或迁移仍需要另有明确范围和授权。同物理主机也不自动代表同一个 Runtime，不能据地址改写登记身份。

负责人只在 Codex 确认具体业务范围，已有同范围确认直接复用。两端确属同一 Runtime 时，AI 使用其既有本机身份完成一次技术确认并应用。多 Runtime 仅兼容已有部署，由 AI 处理端点技术确认，不把机器 quorum 交给业务负责人。Runtime 是企业部署身份，不是个人身份；既有员工角色、应用/模块/Action 权限与管理员可选入口保持。

范围为核心 SKILL、跨系统/原生聚合/管理员初始化参考及 1.1.43 现有 changelog 的文字补充。CLI、host assets、Schema、模板、版本元数据、2.4/2.5、其他 Skills 均不变；`integration_plan.py` Git blob 仍为 `b59f117bb0944a55b0650ebb698c97f4bf28a822`，原始 SHA-256 仍为 `14b246db3fcf4d1eadd639e34df7024c393eb79776e21a30db18f31fbeed53ac`。
