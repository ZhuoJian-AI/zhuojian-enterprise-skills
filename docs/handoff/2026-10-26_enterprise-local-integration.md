# 企业服务器内业务对接与能力漏报修复

## 问题与责任

已获企业服务器 root 维护授权的开发 Codex，仍把企业业务对接交回 SaaS 管理员。本次发现两个独立原因：Runtime 能力查询的本机安全投影漏掉平台已返回的集成计划字段；旧项目规则及交接又把跨系统业务绑定为平台事件/平台跨应用接口先行。root 不能冒充员工的限制本身正确，但不应阻止获权开发 AI 新建受限的企业业务服务。

- Skill：区分开发维护身份、员工 OAuth 宿主及线上浏览器助手；明确企业服务、文件原件交付、结果查询和确定性队列可在企业项目实现。
- Runtime：修复已实现能力的安全投影，不新增平台授权，不向 CLI 输出凭据或任意上游内容。
- 子系统：按当前明确业务授权迁移旧 AGENTS、任务和阻塞交接，在原文件保留历史、修正责任与下一步；真实业务服务与验收仍由企业开发 AI 完成。
- SaaS：公共统一身份、员工权限、平台 Action/事件及工作空间契约继续有效；本次不要求为每条企业业务新增 SaaS 接口。

Skill 发布、Runtime 安装、旧项目规则迁移及业务服务上线分别报告。更新规范或能力字段不代表企业业务已经打通。

## 本次工作流修正

`SKILL.md` 及跨系统、多系统参考把专用企业服务与平台事件分开；没有现成业务接口属于实现工作。已有整体业务范围确认可覆盖三个、四个或全部已列明系统，AI 自行拆分服务关系、机器配置及必要的平台计划，不要求负责人逐项操作管理页面。

`intra-enterprise-service-integration.md` 给出企业 root 实测、旧规则迁移、目标权威服务复用、机器委托、原件流/精确读取委托、幂等、未知回读与整链验收。服务身份与来源员工分别审计，提交、文件和结果查询均核对当前范围；代理员工模式继续验证当前目标权限，不能静默改为机器授权。

员工 OAuth 插件拒绝业务调用后不能以 SSH 代其执行越权业务；另获维护授权的开发 AI 可以修复实现并按真实员工身份重验。公共 SSO、模型网关、员工审批及高风险确认不因 root 服务路径降级或另设 fallback。

能力查询缺字段先核实本机投影与 SaaS 真实响应；需要事件时可在同一 Runtime 通过 `integration_plan.py catalog` 直接检查固定平台接口。Runtime 工具可由企业 root 按备份、精确替换和复查流程维护，不能把脚本升级变成重新初始化企业或暴露登记凭据。
